# GitHub Growth & Achievements Roadmap — 2026

## Objetivo

Melhorar reputação técnica, apresentação pública e contribuição open source. Achievements devem ser consequência de trabalho verificável — não de spam de commits, issues artificiais ou automações criadas apenas para inflar atividade.

> Os critérios de achievements não possuem uma API pública de progresso confiável e podem mudar. Os valores abaixo seguem referências comunitárias atualizadas em 2026 e devem ser reconfirmados periodicamente.

## Prioridades

| Achievement | Critério conhecido | Estratégia profissional |
|---|---|---|
| Pull Shark | PRs mergeados; tiers aumentam com volume | continuar Issue → branch → PR → CI em melhorias reais |
| Quickdraw | fechar Issue ou PR poucos minutos após abrir | usar apenas quando surgir uma correção pequena e real que possa ser resolvida imediatamente |
| YOLO | merge de PR sem review | não perseguir; qualidade e review têm prioridade |
| Pair Extraordinaire | coautoria em PR mergeado | colaborar de verdade com outro desenvolvedor e usar `Co-authored-by` corretamente |
| Galaxy Brain | respostas aceitas em GitHub Discussions | responder dúvidas técnicas em projetos relevantes, com evidência e reprodução |
| Starstruck | repositório próprio com stars suficientes | publicar ferramenta/documentação realmente útil, com demo, README, licença e releases |
| Public Sponsor | patrocínio público via GitHub Sponsors | somente se houver decisão pessoal de apoiar um projeto/maintainer |

## Plano de execução

### Fase 1 — Perfil e repositórios

- perfil `Videirafo/Videirafo` com README profissional;
- portfólio central `Fernando_Videira`;
- 3–6 repositórios públicos realmente apresentáveis;
- README com problema, solução, arquitetura, screenshots/demo e setup;
- CI visível;
- SECURITY e CONTRIBUTING quando aplicável;
- releases/changelog para projetos versionados;
- topics e descrição claros;
- nenhum secret ou código privado exposto.

### Fase 2 — Pull Shark por engenharia real

Toda mudança relevante segue:

```text
Issue → branch → implementação → testes → PR → CI → review/merge
```

Não dividir uma única mudança artificialmente em dezenas de PRs apenas para subir contador.

### Fase 3 — Open source

Priorizar contribuições pequenas e verificáveis em projetos ligados à stack real:

- documentação;
- reprodução de bugs;
- testes de regressão;
- correções pequenas;
- exemplos;
- acessibilidade;
- TypeScript/Python;
- Next.js/React;
- FastAPI/Django;
- Supabase/PostgreSQL;
- tooling e observabilidade.

Objetivo: construir histórico de contribuição externo, não apenas atividade nos próprios repositórios.

### Fase 4 — Galaxy Brain

Responder Discussions onde exista experiência prática. Uma resposta de qualidade deve conter:

1. contexto do problema;
2. causa provável;
3. passos reproduzíveis;
4. solução;
5. limitações;
6. referência/documentação quando necessária.

Não responder perguntas aleatórias apenas pela medalha.

### Fase 5 — Starstruck

Criar um ativo público útil. Candidatos:

- versão pública e genérica do Videira Omega Studio OS;
- templates de engenharia para SaaS multi-tenant;
- starter de documentação UML/C4/ADR;
- checklist de produção para AI Agents;
- baseline GitHub Flow + CI + security para projetos modernos.

Requisitos antes de divulgar:

```text
README excelente
LICENSE escolhida conscientemente
examples/
docs/
release inicial
CI verde
screenshots/demo quando aplicável
issues abertas para contribuição
roadmap claro
```

## Métricas que importam mais que medalhas

- PRs mergeados com contexto e testes;
- issues bem escritas;
- contribuições em repositórios de terceiros;
- stars orgânicas;
- forks e usuários reais;
- releases;
- documentação acessível;
- tempo de resposta a issues;
- cobertura/CI;
- ausência de secrets e incidentes evitáveis.

## Regra anti-farming

Não usar scripts para criar e fechar dezenas de issues/PRs vazios. Isso aumenta números sem aumentar reputação técnica e degrada a apresentação do perfil.

## Objetivo de curto prazo

1. consolidar perfil público;
2. manter Pull Shark evoluindo por PRs reais;
3. obter Pair Extraordinaire através de colaboração legítima;
4. iniciar contribuições externas;
5. escolher um projeto público com potencial real de Starstruck;
6. usar Discussions para compartilhar conhecimento técnico útil.
